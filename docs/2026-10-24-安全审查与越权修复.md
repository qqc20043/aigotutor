# 2026-10-24 安全审查与越权修复（IDOR ×4 + 密钥加密 + CORS/metrics 收敛）

> 背景：项目功能与质量门禁全绿后做的一轮安全代码审查。四个越权漏洞全部
> 先用双用户 PoC 复现、修复后同脚本复验（401/404），132 项端到端冒烟无回归。

## 一、修复清单（PoC 全部复现）

| # | 漏洞 | 位置 | 修复前 PoC | 修复后 |
|---|---|---|---|---|
| 1 | 跨用户读任务详情 | `api/agent.py::task_detail` | B 用 A 的 task_id 读到 200（含代码/Agent 输出） | 404 |
| 2 | 跨用户取消任务 | `api/agent.py::task_cancel` | B 取消 A 的任务 ok=True | 404 |
| 3 | **匿名订阅任务 SSE** | `api/agent.py::stream_events` | 无 token 直接 200 拿事件流 | 401 |
| 4 | 任意用户覆写任意题用例 | `api/problems.py` 三个用例写端点 | B 覆写 A 建题的隐藏期望输出（可伪造判题结果） | 404；创建者/管理员 200 |

共性问题：**接口只验证"登录"（UserDep）不验证"属主"**——submissions 接口
本来就有 `sub.user_id != user.id` 的正确范式，任务与题库两条线漏掉了。

修复方式：

- 任务三件套（detail/cancel/wait）+ SSE 统一走 `core/tasks.py::task_owner()`
  （本地字典 → Redis 镜像，与 task_detail 同一数据源顺序），非属主返回
  **404 而非 403**（不泄露他人任务的存在性）；
- SSE 鉴权用标准 `UserDep`：前端本就用 fetch 消费 SSE（`stream.ts`，
  EventSource 发不了 header 的问题不存在），无需 token 查询参数；
- 题库用例写权限 = 题目创建者或管理员：`Problem` 新增 `created_by` 列
  （Alembic 迁移 `b5e2c9d01a44`，存量行为空 = 仅管理员），创建接口写入
  `user.id`，三个用例端点走 `_ensure_can_edit_testcases`。

## 二、加固项

- **API Key 静态加密**（`security.py::encrypt_secret/decrypt_secret`）：
  Fernet（AES-128-CBC+HMAC），密钥由 `SECRET_KEY` 经 PBKDF2 派生；
  写入加密、读取解密（`deps.get_model_config`）、脱敏先解密再 mask。
  **兼容存量明文行**（解密失败原样返回）；`cryptography` 未安装时退化为
  明文并打警告（保持零服务依赖开发体验，已入 requirements.txt）。
- **CORS 收敛**：`allow_origins=["*"]` + `allow_credentials=True` 会让
  Starlette 回显任意 Origin，等效全开。改为 `AIGOTUTOR_CORS_ORIGINS`
  白名单（默认空 = 同源 only；前端由后端托管、开发走 vite 代理，本就不需要跨源）。
- **/metrics 门控**：设 `AIGOTUTOR_METRICS_TOKEN` 后必须携带（Bearer 或
  `?token=`）；未设置时仅 loopback 可抓。外网默认 404。

## 五、已知边界（如实记录）

- 属主校验依赖运行态（本地/Redis）；任务完成且镜像过期后 owner 不可得，
  此时 detail 本就 404，无泄露面。
- `SECRET_KEY` 轮换会使已存密钥不可解密——按兼容策略原样返回（表现为
  网关 401），用户重填即可；生产建议固定 SECRET_KEY 或做密钥迁移。
- 非属主统一 404 而非 403：有意为之（不泄露资源存在性），管理端除外。
