### 环境谜案：Temp/struct.py 遮蔽标准库

从 Temp 跑脚本时 `from pydantic import FileUrl` 稳定 ImportError（直接 -c 跑却正常）。
逐层定位：**Temp 目录里的 `struct.py`（10-03 某次会话解档脚本的遗留）遮蔽标准库
struct → zipfile → importlib.metadata 链条炸掉 → pydantic 惰性导入的 `__getattr__`
内部异常被 `from X import Y` 吞成 "cannot import name FileUrl"**。改名 `.bak` 后消失。
附带发现：那些一直混在 stdout 里的"神秘 JSON dump"就是该文件被意外 import 执行的输出。
**教训：脚本目录等于 sys.path[0]，Temp 里的任意 .py 都可能遮蔽标准库；pydantic 的
`__getattr__` 惰性导入会把深层 ImportError 伪装成 "cannot import name"。**

## 部署事故：双进程抢 8000 端口（验证时现场抓到）

重启后 POST /interview/start 稳定 405、openapi 无 interview 路径——
**run.py 的多进程 worker 在主进程被杀后留下孤儿 worker 仍占 8000**，
新进程的流量被旧的抢答（openapi 是 72 路径的旧代码）。清掉全部
python 进程（含 multiprocessing-fork 子进程）后 79 路径正常。
**教训：重启 run.py 服务必须连子进程一起清（按 CommandLine 匹配
multiprocessing-fork），只杀主进程会留下"僵尸版本"抢流量。**
