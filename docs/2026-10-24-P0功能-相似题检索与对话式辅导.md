# 2026-10-24 P0 功能：相似题检索（举一反三）+ 对话式辅导（多轮）

> 调研结论驱动（对标 OJ 生态与 AI 教练产品的功能差距）：这两项是投入产出比
> 最高的补齐——一个补"RAG 检索层"的故事，一个补"多轮会话 + 上下文治理"
> 的故事，都直接命中 AI 应用岗 JD 的关键能力词。

## 一、相似题检索（举一反三）—— 轻量 RAG 检索层

**定位**：零外部服务的检索层（SQLite 内建 FTS5 + trigram 分词），题库规模下
比向量库更可控、可解释，不破坏"clone 即跑"。

**架构**（`app/core/similar.py`）：
- **双路召回互补**：标签路（SQL 精确匹配，"同型题"最强信号，不依赖分词）
  ∪ 全文路（FTS5 trigram 子串匹配，中文无分词器也能召回提法相近的题）；
  单路失效不影响另一路。
- **混合排序**：`2.0×标签Jaccard + 0.6×FTS命中归一 − 难度差惩罚`——权重在
  规则层（可复现可测试，与 hint/review 同一哲学）。
- **可解释性**：每条结果带 reason（"同标签 贪心；题面相近；难度 48"）。
- **FTS 维护**：虚拟表不进 ORM metadata 也不进 Alembic（迁移一致性检查比
  较两侧表集合，应用层表会造成不一致）；检索前惰性校验（行数或
  max(updated_at) 漂移即全量重建），毫秒级换永不脏读。

**踩坑（trigram 语义实测）**：trigram 是**子串**匹配且查询词需 ≥3 字——
"区间合并"能召回题面含该串的题，但"合并区间"（乱序）与 2 字标签查不到。
这就是标签走 SQL 而不进 FTS 的原因。

**API**：`GET /api/problems/{id}/similar?limit=5`；前端题目详情页新增
「举一反三 · 同型题」面板（点击跳转，显示候选数与索引状态）。

## 二、对话式辅导（多轮陪跑）

**与单发 hint 的分工**：hint 是"一次要一个提示"（结构化输出，走 Agent
注册表）；chat 是"陪跑到想明白"（自由文本多轮）。刻意不塞进 BaseAgent
注册表——schema 校验与流式自由文本是两种形态，硬套同一基类互相将就。

**强度治理（策略归规则、表达归模型的延续）**（`app/core/chat.py`）：
- 初始强度 = `hint_strength_for(该题最弱标签掌握度, 提交次数)`——与单发
  hint 完全同一口径；
- 用户明确要更多（"再点拨""还是不懂"）→ 升一档，封顶 pseudocode；
  表示想通了 → 降回 direction；中性消息不变；
- **任何档位都不得输出可提交的完整代码**（system prompt 硬规则）。

**上下文预算（token 可控）**：题面 ≤1200 字 + 记忆块（core.memory 聚合
结论，非历史流水）+ 最近 10 轮（每轮 ≤600 字）+ 本轮 ≤2000 字——裁剪
发生在旧轮次与超长输入上，最近信息保真。

**降级链**：真模型失败（超时/坏输出/网络）→ `rule_reply()` 模板化辅导，
degraded=True 照常入库；mock provider 直接走规则模板（离线演示与降级
同一路径）。SSE 失败时降级文本整体补发，前端总能拿到终态。

**Provider 层新增** `complete_chat`/`stream_chat`（消息列表原样透传，无
强结构）：OpenAI 兼容 / Anthropic / Gemini 三家原生实现。

**数据模型**：`chat_sessions`（绑定题目 + 强度状态）+ `chat_messages`
（role/content/strength/degraded），迁移 `c8f1a37d02b5`。

**API**（`app/api/chat.py`，全部属主校验——安全修复后的新范式）：
会话 CRUD + `POST /sessions/{id}/messages?stream=true`（SSE：open →
token* → done）。前端新增「对话辅导」页（会话列表 + 气泡对话 + 流式
光标 + 强度标签），从题目详情页一键进入。

**踩坑（SQLite 写锁）**：流式路径先在外层请求事务写 user 消息、再在
SSE 生成器里开新事务写 assistant 消息 → `database is locked`（SQLite
单写锁 + 外层未提交）。修法：**流式路径的所有写入合并到流结束后的单一
事务**（用户消息 + 助教消息一起落），请求事务只读。

## 三、真模型验证（deepseek @ 网关，全程 degraded=False）

**相似题**：12 题库索引重建，返回按混合分排序的同型题（活动安排 0.631 >
区间合并 0.619，理由含共享标签与难度）。

**对话三轮**（demo 绑题会话，初始强度 key_observation）：
1. 「完全没思路」→ key_observation：点出字典序比较方向与边界检查，不给步骤；
2. 「再点拨一下，还是不懂」→ **升档 pseudocode**：拆成两个引导性小问题；
3. 「我想到了！先按左端点排序再线性扫描」→ **降回 direction，且教练结合
   题目上下文纠错**（"这是区间类题的套路，本题输入是整数 n，方向错了"）——
   多轮上下文让模型能识别用户的错误迁移，这是单发提示做不到的。

6 条消息全部落库，会话强度按治理规则流转。

## 五、遗留与演进方向（如实记录）

- 相似题的 LLM 重排（rerank）是明确的演进方向：当前纯检索层可解释性优先，
  加重排即成为完整"召回+重排"两级 RAG；
- 对话辅导未接入会话级 token 统计上报（AgentRun 统计表按 Agent 粒度）；
- FTS trigram 对 2 字标签无能为力——由标签路覆盖，文档化即可。
