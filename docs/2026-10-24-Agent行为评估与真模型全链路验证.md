| 坏 JSON 修复层 | `app/core/agent.py::repair_broken_json` | 网关不守规矩时的兜底（见缺陷 8） |

评估哲学（与 hint/quality 两阶段评分同构）：

- **策略归规则，表达归模型** —— 期望值从 `rules.py` 现算（如提示强度、
  复习排序基线），golden set 不维护第二份口径；
- **断言的是 pipeline 最终输出**（postprocess 之后），即系统承诺给用户的东西；
- **mock 下全绿是回归线**：mock 是"无信息的模型"，它都遵守不了的约束，
  真实模型更没有借口；主观表达质量留给真模型抽样 + 人工审阅。

## 二、真模型评估三轮迭代（provider=openai，deepseek-v4.1-flash @ 网关）

| 轮次 | 结果 | 降级 | 耗时 | 关键失败 |
|---|---|---|---|---|
| R1 | 10/11 | 3 | 151.8s | review×2 + recommend 全部降级；mastery-high 断言失败 |
| R2 | 11/11 | 3 | 145.3s | 数据全绿但 review×2 仍是规则兜底（tokens=0） |
| R3 | **11/11** | **0** | **88.5s** | 全部真模型输出，重试消失 |

每轮降级/失败都抓了模型原始输出定位根因，共修出 **8 个真实缺陷**——
全部是"mock 全绿但真模型必挂/规则层自相矛盾"类，单测无法发现：

1. **mock 对 ReviewPriorityOut 没有 prompt-aware 路径**：静态 FIXTURES 的
   固定 id 不在任何候选里 → postprocess 全部过滤 → 每次都回退规则引擎。
   后果是 mock 下 review 的模型路径从未被测过。修复：`_review_from_prompt`
   遵从规则基线排序（与 mastery/quality 的"无信息层恒等映射"同原则）。
2. 🔴 **规则层强弱项重叠**（`rule_mastery`）：标签数 ≤3 且全部正确率 >0.6 时，
   `ranked[:3]` 与 `ranked[-3:]` 命中同一批标签，同一知识点同时出现在
   "弱项"与"强项"（UI 自相矛盾）。评估首轮即暴露。修复：弱项在强项之外取。
3. 🔴 **零样本档位口径不一致**：`rule_mastery` 零样本分支硬编码 `level="L3"`，
   而 50 分按主路径映射应为 L2——同一分数不同路径展示不同档位。
   修复：档位映射收敛为 `rules.mastery_level_for` 单一来源，两条路径共用，
   评估断言（checks.py）也引用同一来源。
4. **review 预算 0 语义歧义**：规则层把 0 当"不限时"，但模型按字面算
   "0 分钟 ÷ 15 = 0 道题"，返回 `ordered: []` 撞上 schema min_length=1
   （真模型三次输出全同型）。修复：`build_user` 把"不限时"显式表达为
   `null` + `budget_note` 写明口径；system prompt 补"ordered 不能为空"。
5. **RecommendOut.tags 必填 → 真模型稳定漏字段**：deepseek 三次全漏 tags
   （`Field required` → 整单作废重试 → 降级）。修复：schema 放宽为默认空 +
   postprocess 按 problem_id 从候选回填（事实性内容以候选数据为准）。
6. **可推断字段必填 → 同型失败**：`ReviewPriorityItem.order`（模型从不复述，
   postprocess 本来就会重编号）与 `HintOut.hints` max_length=3（模型偶尔
   多给一条手算验证，postprocess 本来就会裁剪）。修复：order 默认 1、
   hints 上限放宽到 6，交由 postprocess 收口。
7. **ReviewPriorityOut.strategy 必填 → 模型自创同义字段**：ordering_intent /
   notes 都实测出现过。修复：strategy 允许缺省，postprocess 用规则口径回填。
8. 🔴 **坏 JSON 修复层**：模型在中文句子里写 `符合"先难后易"的编排意图`，
   未转义的 ASCII 引号直接打断 JSON，且**网关无视 strict json_schema**
   （response_format 被忽略），三次重试同型全灭。修复：`BaseAgent.parse`
   增加 `repair_broken_json`——逐字符扫描，字符串内"后面不是结构性字符
   （, } ] :）"的 `"` 判定为值内引号并转义。

另修 **MasteryAgent.postprocess**（真模型实测把 85.3 分基线评到 68、
同一标签同进强弱项）：分数夹紧到规则基线 ±15（新增 `MASTERY_RADIUS`，
与 QUALITY_RADIUS 同构）、强弱项互斥、并删掉"过滤后为空就回退未过滤
列表"的幻觉通道。

**经验沉淀**：schema 对"模型会漏/会多/会换名字"的字段要宽容（默认值 +
postprocess 补齐），对"事实性字段"要收口（强度/verdict/候选范围模型无权
决定）。前者省掉整单重试，后者保证可复现——两层合起来才是
"结构化输出能扛真模型"的完整答案。

## 四、用法

```bash
# mock 全量（离线、秒级、与 CI 同口径）
python scripts/eval_agents.py

# 真模型抽检（provider/网关从 AIGOTUTOR_* 或 LLM_* 环境变量继承）
python scripts/eval_agents.py --provider openai

# 只跑部分 Agent；改提示词前后各跑一份报告做对比
python scripts/eval_agents.py --provider openai --only hint,review
```

报告输出 `evals/reports/eval-<时间戳>.{md,json}`（不入库），结论沉淀到本文档。

## 六、遗留边界（如实记录）

- 网关不支持 strict json_schema——已用"schema 宽容 + postprocess 收口 +
  坏 JSON 修复"三层兜底；换支持 json_schema 的模型/网关只会更稳。
- mastery 的真模型分数被夹紧在基线 ±15：这是设计承诺（两阶段哲学），
  不是模型能力上限；窗口大小由 `MASTERY_RADIUS` 统一调整。
- review 排序保真度断言（tau≥0.6）在候选分差刻意拉开的场景下验证；
  真实数据里分差小的题允许模型按表达重排，tau 会自然回落但不破线。
